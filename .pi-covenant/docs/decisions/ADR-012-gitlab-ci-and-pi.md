# Complete the GitLab module and Pi tool

GitLab now implements repository and CI reads, bounded trace windows, project-scoped opened-MR lookup, and exact-target pipeline retry/cancel. The Pi tool exposes the eight public actions. The MR lookup is a private module port.

Foundation maps a closed request schema to fixed REST paths and contains credentials. The installed Pi extension uses a host and an explicit glab file. A human confirmation in Pi supplies target-specific authority for interactive calls. A programmatic host can supply its existing task authority through the same callback. Headless Pi calls lack that confirmation and return a blocked mutation result. This is the authorization mechanism chosen for this integration because Pi tool parameters cannot prove what the user authorized. A session lock spans the confirmation, preflight and dispatch, keyed by host, numeric project and pipeline.

Retry and cancel now require an explicit repository in the public schema as well as a pipeline ID. The active repository read still uses the original validated lookup. Cursor validation checks the locally resolved host, path and full query before the project GET, then checks the numeric project ID before fetching the page. A missing or contradictory continuation fails closed. Public lists return one page, while bounded private scans support opened-MR lookup and retry preflight. MR absence is scoped to the selected project's endpoint and source identity. Offset pagination observes a changing collection and is not a transactional snapshot.

Trace offsets are decompressed source bytes. The host scans up to 16 MiB including credential overlap and a continuation byte. It masks matching bytes before returning the window. Malformed or split UTF-8 gets a warning, with an ASCII fallback if replacement would exceed the requested byte cap. The transport retains its 2 MiB JSON limit, rejects redirects, retries eligible reads once and invokes a write at most once. A canceled pipeline state observed in a matching reply supports cancellation confirmation. If an already canceled pipeline is observed before sending, the result reports no change with that observation.

The previously checked mutation and collection models move into the active design manifest with real conformance bindings. The modeled Confirm action describes acknowledgement of a sent cancellation. Model evidence is finite and does not establish remote availability, wire behavior, cross-session coordination or atomic provider pagination. Temporary Git and loopback HTTP fixtures exercise actual requests. The Pi SDK loads the extension with a temporary credential file and runs repository, pipeline and trace calls. No live server or production credentials are required for these checks.

API references are the [GitLab pipelines API](https://docs.gitlab.com/api/pipelines/), [jobs API](https://docs.gitlab.com/api/jobs/), [merge requests API](https://docs.gitlab.com/api/merge_requests/), and [REST pagination documentation](https://docs.gitlab.com/api/rest/#pagination).
