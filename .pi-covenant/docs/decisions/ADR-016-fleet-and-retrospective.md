# ADR-016 Fleet and retrospective

Fleet accepts IDs from a trusted host inventory containing absolute checkout paths and optional local comparison refs and manifest lists. It never fetches. Status and versions preserve per-repository outcomes. Node manifest discovery uses root declarations, including pnpm workspace YAML, with confined, bounded directory expansion. Filesystem, Git and manifest parsing use executable fixtures.

The retrospective is an explicit Pi command. Review uses bounded references to failed harness tool results to propose concrete changes. It reads the owning contracts and backlog and links affected obligations. It records draft proposals without a model call, product changes or follow-up turn. The backlog is Markdown with an embedded versioned JSON block. A host lock and atomic replacement protect exact normalized-title deduplication and stable HBR allocation. Only the current session or an explicit ID in its Pi session directory is available. Raw tool output and transcript text stay out of the automatic backlog.

The finite models cover two Fleet rows and one normalized proposal under explicit or dry-run authority. The executable checks exercise Git, filesystem containment, locking, manifest provenance and Pi registration.

Before implementation, Covenant exhausted 27 Fleet states and six retrospective states. Both models caught both deliberate faults in runs `1795165116466832000-81826` and `1795165118210131000-81843`.
