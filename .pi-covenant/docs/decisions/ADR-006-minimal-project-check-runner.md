# Minimal repository check runner

The user replaced the broad project-CLI authoring scope with a small repo-specific runner. The implemented public surface is inspect plus check, with one CLI command: project check. Existing PROJECTCLI-001..018 meanings remain unchanged; unrelated authoring/maintenance obligations and legacy executor ports remain draft and deferred. PROJECTCLI-010 and 014 apply to read-only inspection and truthful failed checks. New obligations 019..024 cover this version. No generation framework, repairs, preview, Storybook, universal E2E, shipping or runtime Covenant dependency.

Read project-checks.json first. It declares a nonempty list of required checks (id, executable, argument vector, optional relative cwd and timeout_ms). Otherwise prefer a repository-owned check or verify package script, then available typecheck, lint and test scripts. Build and E2E require explicit repo configuration or inclusion in its aggregate command. This is bounded static Node discovery, not interpretation of arbitrary instructions: non-Node repos provide explicit configuration.

All checks are mandatory. Validate the complete plan before execution, run sequentially and stop on first failure. Remaining checks are not_run and cannot support pass. Positive finite per-check deadlines and host cancellation fail closed. Diagnostics are capped and explicitly marked when truncated; known successful completion does not depend on log length. Contained canonical working directories prevent accidentally running in another repository; commands are trusted project code, not sandboxed.

Model-first: two mandatory checks represent the completion/dispatch state machine. Check NoFalsePass and NoDispatchAfterCancel, challenge premature success and dispatch after cancellation, then implement ordinary TS-Effect and bind real process/CLI tests to modeled actions. Model checking proves finite safety within declared assumptions; it does not prove command adequacy or eventual termination.

Review clarification: the initial local draft treated truncated diagnostics as failed execution. That would fail successful verbose checks solely because their logs exceed a display cap, contrary to the requested minimal runner. PROJECTCLI-022 now separates bounded diagnostic display from observed completion/exit status. A new real-process acceptance case requires exit-zero verbose checks to pass with truncated=true. This does not change Covenant model-checker completeness rules or its structured evidence requirements.

Discovery revision: ADR-007 records the user-requested replacement of name-only aggregate short-circuiting with a complete static inventory, evidence-based aggregate coverage and visible per-project E2E selection. Completion and failure semantics are preserved.
