# GitLab repository and CI brick

Status: design proposal; no GitLab runtime implementation or Pi registration is introduced. The user's existing decisions retain eight public actions: repository, pipelines, pipeline, jobs, job, logs, retry and cancel. The ninth provider operation lookup_open_mrs stays private to MR consumers. MR metadata/discussions, merge, deploy, job play, pipeline creation/deletion and arbitrary API requests remain excluded.

Use the existing repository-context owner for local target discovery, GitLab for typed service mapping/policy, and foundation for credential-bearing transport, authorization provenance and per-pipeline coordination. Preserve the local context fields used by worktree/project checks; the new optional gitlab_target is a planned observation, not an already implemented resolver feature. No feature module receives raw tokens or imports foundation.

Prefer a bounded single-send HTTP host transport, with a host-owned credential bridge able to reuse a selected glab host credential. The installed glab 1.111.0 API command was audited as a useful read fallback, not assumed to be a strict mutation transport: it exposes headers, streams non-color output, and calls HTTPClient.Do, but does not expose redirect suppression. Mutation delivery requires redirects/replays disabled and a local fake-server assertion of one POST, including 307/308 and connection-loss cases. Do not invent `glab auth token` (not an installed command), parse human auth-status output, or depend on repository-local credential overrides. An explicit host token provider may substitute for the glab bridge; credential transport remains the same typed port. PAT/OAuth access-token support must be demonstrated in the first slice; interactive login, refresh workflows, job tokens and unsupported credential backends return actionable prerequisites rather than silently changing authentication. No configured secrets are written to project files.

Remote selection is deterministic: explicit host/project selector, otherwise an explicit configured remote, otherwise a single distinct eligible fetch remote. Equivalent SSH/HTTPS URLs deduplicate by host/project. Multiple distinct candidates block; origin is not inherently privileged. Supported URLs are HTTPS, ssh:// and scp-style Git URLs; SSH aliases/nonstandard API prefixes require host mapping. Explicit cwd and repository conflicts block. Detached HEAD allows ID-based CI reads but cannot invent a source branch for MR lookup. An explicit remote repository can be read without a checkout; writes still require exact host-supplied action/project/pipeline authorization. Host allowlisting and credential association precede any credential-bearing request.

Preserve existing draft obligation meanings. Add atomic lifecycle/transport obligations and exact planned acceptance identities, retaining draft status and empty native implementation bindings. Schema refinements make empty-project default_branch nullable, retain optional job ref, and distinguish source trace bytes from returned redacted bytes and known continuation. These are unimplemented DTO refinements; no active runtime meaning is weakened.

Model finite mutation and collection-evidence policies before implementation. Keep a candidate manifest under models/gitlab rather than adding unimplemented conformance targets to the active harness manifest. Current Covenant conformance requires active bindings for every declared modeled obligation, so mixed implemented/pending models cannot yield a full conformance pass. Verify the proposal through the existing native CLI in an isolated snapshot; explicitly demonstrate that conformance reports implementation pending. This is a workflow limitation, not permission to treat design as implementation or to weaken conformance. The harness's separate full pnpm check continues to verify its implemented scope.

Implement in slices: target/auth/transport; repository and CI reads; trace windows plus shared MR lookup; retry/cancel lifecycle; additive Pi registration. Each slice starts with real executable acceptance and activates only obligations actually covered. No live pipeline mutations are part of design checking or a routine smoke test.
