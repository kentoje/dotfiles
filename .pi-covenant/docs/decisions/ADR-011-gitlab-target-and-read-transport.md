# GitLab slice 1: target resolution and authenticated reads

Implement repository lookup as the first useful read over the new target/transport boundary. Pipeline/job/log operations, mutation authority, coordination and Pi registration remain deferred. Existing GitLab obligations covering those complete surfaces stay draft; scoped GITLAB-018/019, FOUNDATION-008/009 and REPOSITORYCONTEXT-009 cover this slice. GITLAB-001/003 activate only against actual lookup/context and read-only behavior. The reserved gitlab.authorization test remains deferred with mutation authority; a read-only capability does not prove authorization for future POSTs.

Opt-in repository-context discovery reads bounded local Git config fetch URLs without Git subprocesses. Explicit selectors override defaults; an explicit checkout plus conflicting service selector blocks. Equivalent allowed remotes deduplicate and distinct choices block. Ordinary worktree/project calls do not enable this discovery and retain their existing context behavior. Current scope supports simple local remote URL declarations; includes, remote helpers, dynamic URL rewriting, non-ASCII paths and unmapped SSH aliases/ports do not become inferred effects. A remote-only selection has no invented local branch or HEAD.

Foundation owns host-to-API-origin mapping, credentials, bounded HTTP, redaction and cleanup. Only exact allowed targets obtain a credential. The sole transport operation is repository GET; manual redirects prevent credential forwarding/replay. At most two eligible transient read attempts share the original deadline, including credentials and Retry-After. Host replies cross the feature boundary only after bounded UTF-8/JSON decoding and configured-secret redaction; raw error bodies and exception messages are never exposed. The GitLab module independently validates complete project identity and web origin before success.

The default bridge reads an explicitly supplied regular global glab YAML file and selects only its exact hosts entry. It does not assume `glab config get --global` isolates credentials: the audited get command delegates to configuration lookup, whose implementation supports environment/local fallback. No child CLI is needed for file-backed PAT/OAuth access tokens. Keyring-authoritative entries, refresh flows, job tokens, aliases and missing tokens return an actionable prerequisite; a trusted credential callback can supply supported secure-storage integration. No fallback to another host, global token field, environment token or project config occurs. Live credentials are not needed for acceptance.

A separate repository-read TLA+ model is checked before implementation: 52 finite states under allowed-host/credential dispatch, at-most-two attempts, no dispatch after stop and truthful complete response. Four deliberate faults challenge those invariants. Executable local HTTP/config/Git tests establish parser, bytes, headers and resource behavior; model evidence alone does not. The earlier two CI/mutation models stay candidate designs with implementation pending, without fake conformance bindings.

TypeScript ambient libraries include ES2024/DOM for Promise.withResolvers; emitted target remains ES2023 and the already required Node 24 runtime supplies this API. No CI is enabled, no product-session Covenant gate is added, and no mutation or global Pi settings are changed.
