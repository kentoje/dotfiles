## Context and decision

The user replaced the fixed verify abstraction with tailored project CLI creation and maintenance. Existing E2E can be exposed when appropriate. The agent may propose creation; acceptance or an explicit creation request authorizes it.

## Implementation consequences

Create and maintain repository-owned CLIs with explicitly agreed, project-specific capabilities. Discover existing project commands and tools; no universal check suite or real-app driver is imposed.

Executable tests and implementation do not exist yet. Acceptance scenarios are recorded in ../../../docs/acceptance-scenarios.md and must become real tests before obligations are activated.
