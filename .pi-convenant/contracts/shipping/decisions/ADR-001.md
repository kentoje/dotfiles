# Shipping design scope

Status: accepted design direction from the conversation on 2026-11-03. Obligations remain draft.

Obligations: SHIPPING-001, SHIPPING-002, SHIPPING-003

## Context and decision

The user said an MR is not always required, shipping must be specified, a custom /ship command is an option, and blocked completion must not trigger another agent turn.

## Implementation consequences

Separate ordinary task completion from explicitly requested shipping. Report blockers without automatically waking the agent. A /ship command remains a candidate interface, not a finalized action contract.

Executable tests and implementation do not exist yet. Acceptance scenarios are recorded in ../../../docs/acceptance-scenarios.md and must become real tests before obligations are activated.
